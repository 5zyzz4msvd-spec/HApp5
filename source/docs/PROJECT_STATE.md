## 一次性工作流

每个需求只走一次下面的顺序，不要做完前端又回头补变量，也不要为了确认反复抽检 PNG。

如果需求跨越变量、世界书、前端正则、酒馆助手脚本中的多个层级，优先使用 `docs/MULTI_AGENT_WORKFLOW.md`：由统筹 agent 分发最小任务合同，专门 agent 只读自己的锚点文件。

1. **判定改动层**
   - 改手机界面、按钮、暂存、渲染：改 `scripts/mirror-frontend.mjs`，不手改生成出的 HTML。
   - 改变量叶子、默认值、范围或对象严格性：先改 `scripts/mvu-schema-contract.mjs`，再同步 `scripts/finalize-card-v1_6.mjs` 的 init、变量列表和更新规则。
   - 改世界书、正则、初始数据：改 `scripts/finalize-card-v1_6.mjs`。
   - 改成就/任务数据库：直接改 `src/reward-defaults.js` 或卡内 `data.extensions.workbench.rewardDatabase`。
   - 改独立成就任务工作台：改 `src/app.js` 和 `src/styles.css`；它不应该参与前端渲染或保存中间产物。

2. **先变量/世界书，后前端**
   - 如果一个功能需要新变量、世界书解释、AI 更新规则，先在 finalizer 里定义。
   - 前端只消费已经确定的变量名，不临时发明第二套字段。

3. **前端内部应用四件套**
   - 新增或重做手机应用时，同步处理主屏入口、`clearPhoneInternalOverlays`、`detectPhoneApp` 和首页补丁排除列表。
   - 应用页只挂在手机根容器里；动画/遮罩也只 append 到手机根容器，不要 append 到 `document.body`，否则会盖住右侧暂存区。
   - 旧 React 顶栏和新灵动岛不要共存。重做页面时优先删旧顶栏路径，再补内部页。

4. **生成本地前端一次**
   - 需要前端变化时运行 `node --check scripts/mirror-frontend.mjs`。
   - 再运行 `node scripts/mirror-frontend.mjs`。
   - 手机端由桌面端镜像派生；前端变化后运行 `node --check scripts/build-phone-frontend.mjs` 和 `node scripts/build-phone-frontend.mjs`。
   - 生成后用 `rg` 检查关键函数/类名是否进入 `public/frontends/hypnosis-app/index.html` 和 `st-load-inline.html`。

5. **封装和结构抽检**
   - 改变量、世界书、正则、默认变量或远程 commit 时，运行 `node --check scripts/finalize-card-v1_6.mjs` 和 `node scripts/finalize-card-v1_6.mjs`。
   - 发布前运行 `npm run verify:card` 检查本地版和发布版成品 PNG，而不是只搜索 finalizer 源码。验证器会确认：成品恰好含一份启用的当前 Schema；关闭的 init YAML 能通过 Schema；未知旧键自动迁移时保留且显式清理才删除；跨页/旧路径整批拒绝；完整性清单、运行时 gate、篡改负例及正常升版重签正例；旧 `<update>` 消失；常驻 MVU 提示没有超预算；默认四名角色和前端入口完整。
   - `verify` 失败时先修生成真源再重新 finalizer；禁止为了让验证通过而把断言降级成源码字符串存在性检查。

6. **远程发布只交给远程发布 agent**
   - 只有用户明确要求远程卡时，才运行 `npm run publish:card` 或 `node scripts/publish-card.mjs`。
   - 这个脚本默认发布当前工作树的 v5.0 可维护源码与已经生成好的桌面端/手机端前端；它会同步根级 `source/`，覆盖同级 `dist/`，创建候选 commit，用该 commit 回写并验证发布版 PNG，最后才推进远端 main。
   - 脚本默认不重新运行 `scripts/mirror-frontend.mjs`，避免把未验证的前端补丁混入发布。只有确实需要发布时顺便重新生成桌面端，才使用 `HYPNOOS_RUN_MIRROR=1 node scripts/publish-card.mjs`。
   - 发布前必须已通过 `npm run verify:card`；发布脚本完成后还必须再跑一次 `npm run verify:card`。若发布后失败，修源脚本并重新发布新的 dist commit，不交付失败 commit。
   - `HApp5/source/` 是授权的 Fork 源码快照；当前开发仓库仍不提交或推送。源码快照排除 `.git`、`node_modules`、`tmp`、`public/cards`、忽略文件、缓存和敏感凭据。
   - 不手动复制第二张本地卡，不手动维护无版本 PNG。

- 项目里的变量路径以 MVU 根为准，例如 `/系统/当前时间`、`/角色/犬冢夏美/状态/好感度`；给 AI 或项目封装的 JSON Patch path 不额外加 `stat_data`。
- 模型输出仍使用标准 JSON Patch `add` / `replace` / `remove`；Tavern Helper 只在 `COMMAND_PARSED` 后把它们转换成内部 `insert` / `set` / `delete`。世界书与模型输出不得使用 `op:"insert"`。
- `stat_data` 是角色卡内部总数据根，只在解释内部结构或兼容底层接口时提；日常世界书和前端操作提示使用 `/系统/...`、`/角色/...`。
- 避免频繁读角色卡世界书或 MVU。能在进入应用时读一次，就不要每次点击页内按钮都读。

## 变量与货币现状

- `成就和任务`：固定任务接取仍由前端直接写入变量并保留可选内部`任务ID`；“新增”页当前保持上锁，但底层每日任务事务已改为前端先创建轻量占位。每日任务对象只含`任务、完成条件、奖励星光点、奖励物品?、已完成`，不保存`任务ID、每日任务日期、任务目标、已领取`；日期、目标与一天一次锁保存在当前聊天的前端奖励状态。额外变量模型只可replace该真实根键下的`任务`与`完成条件`两个精确叶；正文必须自然写出`{{user}}`拿起手机接取任务、看到APP通知及现场人物反应，正文模型不得输出任务补丁。领取或取消均由前端发奖并直接删除任务根，不写领取墓碑。变量与暂存合计仍最多3项。界面使用方正黑框卡片与报纸剪字标题；灵动岛固定显示`TASK`。酒馆助手脚本只在变量中存在严格`已完成:false`的任务时动态注入最多三项真实根键、完成条件与精确路径。
- `库存`：使用无背景图的P5八向轮盘，一页8件物品；中央手枪会在鼠标悬停、键盘聚焦或点击物品时按顺/逆时针中的最短角度旋转瞄准，避免跨零度时原地绕一整圈。选择物品会先播放枪口火焰、曳光与`KIA!`冲击字，再完成选中；左右分页分别播放`BANG!`与`PIA!`并把枪口固定到左/右分页方向，换页后不被新页第一项覆盖。下方完整展示物品名、数量与描述，`ITEM DATA`标牌不得被裁切；灵动岛固定显示`ITEM`和箱包图标。“使用物品”弹窗继承库存黑白猩红视觉，不再复用人物档案纸张弹窗。
- `催眠APP`灵动岛内的MC能量进度条使用仅限催眠APP的哥特单轨样式：暗纹空槽、酒红能量填充与旧金收束边，不影响其他应用的灵动岛进度条。
- `地图/学校/特殊地点`：地图显示当前地点变量，不要求地点存在于前端列表；地点列表只有明确更新时才变。“更多区域”外置弹链与手机内抽屉共用新增入口，外置弹链一页最多6项并保留独立“＋”。新增地点默认只写当前聊天的前端地图存储，不写MVU或暂存区；用户可直接填写保存，也可调用设置中的独立文生文插头补全名称、分类和说明，模型结果必须先回填表单、经用户确认后才保存。
- 外置`课程表`采用纯手绘纸张风格，列标题使用月曜日至金曜日；朝礼、昼休み、終礼、清掃和放課後独立展示。周课表之外固定显示本日列和 USER 日程列，节假日由本日列切换说明。课程魔改永久绑定本聊天的星期＋课节单格，但不属于规则或催眠效果。
- `旧校舍/灵异线`：入口始终使用当前校园地图内弹窗，不切换独立节目。满足三名角色条件后由千杀百花察觉亡魂，确认操作以跨资源事务创建弥留子、启用灵异世界书、写入线路1并锁定暂存；失败回滚本次新增。线1满足深雪与弥留子好感条件后，在确认前不泄露二人联系；确认操作启用附身世界书并原子写线路2与唯一宿主深雪。线2后人物档案姓名左侧显示鬼魂图标，附身、切换和取消均由前端直写并锁定暂存。
- `USER日程`：按剧情日期保存六个行动格，只锁当前时刻之前的格子，恰好到点及未来格可用；未真正跨日不会刷新机会。所有手机操作先进入待安排池，再由用户拖入具体未来格；基础行动与独立备注各占一次机会，免行动与催眠卡作为不占机会的附加项也需安排时间。执行会从当前可用格自动推进到最后一个有内容的格子。赌博APP含21点与数字弹仓轮盘，全部由前端即时结算，多局只聚合成一张行动卡并仅记录胜负及净收益。原打工、打工偶遇、工资、社畜值和打工buff机制已整体退役。

- orjenrn 邂逅包的全部角色必须有可读取证件照。原本缺图的白鸟结衣、德川喜广、凤条瑠衣、九条凛音、尼子纯、浅仓步美、鹰司千代已按各自人设补入 `role-18.png` 至 `role-24.png`；统一沿用九条樱的1086×1448浅色纸纹正面胸像规格与半写实日系厚涂质感。证件照只体现年龄、发型、身份服装与公开气质，保持完整正常着装，不采用世界书中的私密情节。发布验证要求 orjenrn 每个角色图片路径非空、文件存在，并固定检查这7张的PNG规格。
- `帮助`：手机内简要说明其他应用。
- `设置`：顶部分为“聊天与变量 / 模型插头”两段。聊天备份可导出当前聊天的完整消息、全部滑动候选、聊天元数据、每层MVU变量，以及绑定当前聊天的 localStorage、sessionStorage、邂逅 IndexedDB、人物照片和场景剪影；导入会覆盖当前聊天及其前端存储，失败时回滚。自动导入与版本迁移只执行确定的别名迁移并保留未知键和既有值，不做隐式 clamp/coerce/补字段；设置页会分别报告未知键和类型/枚举/范围错误，只有用户明确确认“清理/矫正”才运行显式规范化。模型插头只保留独立文生文配置，支持同源代理/Secret Ref或OpenAI-compatible直连、上下文开关和测试；持久配置是设备全局设置，不随聊天备份导入导出，直连API Key只存当前浏览器session且不进入日志、提示词、暂存区或变量。独立请求可按开关只读最近剧情、时间地点事件、相关启用世界书和用户备注，失败不回退聊天AI。照相仅保留前置自拍上传和保存，读取`/系统/_user身份/照片`；后置摄像头不实现。导入、变量矫正、固定内容刷新和线路世界书覆盖均使用设置页自己的深蓝前端确认弹窗；邂逅草稿与地图删除也不再调用浏览器原生确认框。全局界面偏好不随聊天备份覆盖。

## 暂存区规则

- 每条暂存统一派生四种变量归属：`前端已结算`、`AI结算`、`协同交接`、`仅叙事`。暂存卡摘要显示 `AI不动/AI写` 项数，展开详情显示精确路径；同一路径不会在同一操作里同时落入两类。
- 发给 AI 的每条操作都直接携带 `AI不动` 与 `AI写`；AI只处理该项 `AI写` 路径，`AI写=无` 时按钮不产生补丁。同路径若在后续操作变为 `AI写`，从 `<相关变量>` 的前端后值继续，不重做前端差值。
- 已有数字变量在推理层先确定增量，再用当前值加增量并按 Schema 钳制；标准 JSON Patch 的 `replace.value` 仍只写最终绝对值，不引入 `delta` 操作。初始化、时间、阶段、固定配置和明确重置直接写目标值。
- 重复点击“写入输入框”会替换旧的 `<本轮操作>` 容器，不会追加第二份同批暂存。
- `<本轮操作>` 仍是唯一送给 AI 的语义容器；显示正则只在用户消息生成带恢复标记的折叠卡。若外层消息模板把卡片再次转义，前端与时空/Galgame 共用的宿主观察器会从同源 `rawData` 读取版本化边界标记，只复制纯文本并按白名单重建变量权限、AI提醒、来源和操作项的嵌套组件；破损标记只降级为纯文本，不注入原始 HTML。恢复仍以“可见区含操作标记”为条件，防止历史楼内容复活。
- `<相关变量>` 只保留一次性余额/状态纯快照，不是 MVU 路径，也不再拼接重复的“不得再次结算”警告。
- 锁定显示分为结果锁、事务锁和跨楼锁：前端副作用、等待AI一次性结算、跨回复流程不再混成同一种提示。
- “确认写入后不清空暂存”由暂存区复选框控制。
- 持续状态提醒与一次性业务操作必须使用互斥的精确操作名；禁止用前缀或包含关系替换/清理。当前持续项只精确匹配`警视厅关注`和`作弊模式进行中`，不得命中`作弊模式启动`或`作弊模式关闭`等真实操作。旧版打工/派遣操作只在旧聊天队列恢复迁移时丢弃，运行时不存在反复清理函数。

- 人物档案桌面的迷你卡无论当前记录为“常规”还是“深层”，底部摘要都固定展示衣着四项，避免桌面信息密度随子页跳动；“深层”只切换整张卡的暗色主题、深层页按钮组和标题，“常规”保持浅色主题与常规按钮组。

- 人物档案 prev/next 保持原有角色索引语义；next 的入场纵向位移和斜切扫光已做成 prev 的完整镜像，宿主框外相邻人物 rail 也只动画本次点击的一侧。

- Galgame 人物演出不改输出标签、解析、头像选择、绰号或人物档案跳转；宿主与完整前端的两套卡片保持统一 P5 黑白红骨架，并按本次出场角色稳定分配不冲突的角色强调色、ACT 编号与正文侧标，让多人演出可一眼分组。
- 成就/任务短标签继续使用报纸裁剪字；成就名、任务名、长描述、任务奖励和新增任务页正文统一为连续黑底白字，不再对长文本逐字轮换底色。
- 可删除人物的按钮只显示原创击破/终结图标，删除说明仅保留为`aria-label`，不再绘制垃圾桶或“删除档案”文字。

## 发布脚本行为

`npm run publish:card` 固定做这些事：

1. 默认跳过桌面端 mirror，发布当前 `public/frontends/hypnosis-app/`；若设置 `HYPNOOS_RUN_MIRROR=1` 才先运行 `scripts/mirror-frontend.mjs`。
2. 运行 `scripts/build-phone-frontend.mjs` 生成手机端。
3. 从 `git ls-files --cached --others --exclude-standard` 收集当前工作树，把可维护源码同步到远端根级 `source/`；删除的源码会从该受管目录移除，忽略文件、缓存、本地卡与敏感凭据不得进入快照。
4. 用当前 `public/frontends/hypnosis-app/` 覆盖同级 `dist/webview/`，排除 `source.html`。
5. 用当前 `public/frontends/hypnosis-app-phone/` 覆盖 `dist/phone/`。
6. 若源码或 dist 有变化，先建立临时候选分支；不得在发布卡验证前推进 main。
7. 用候选 commit 的 immutable SHA 运行 `scripts/finalize-card-v1_6.mjs`，重建发布版 PNG。
8. 对候选 commit 绑定的发布卡运行发布验证与 finalizer 幂等验证。
9. 全部通过后快进远端 main 并删除候选分支；失败则清理候选分支，main 保持不变。
10. 只回写本地发布卡输出；`public/cards/` 是 ignored 产物目录，不进入 `source/`。
11. 发布后运行 `npm run verify:card`，确认本地卡写入了最终 commit-pinned CDN URL，且远端 `source/`、`dist/` 同属该 commit。
12. 当前开发仓库不由发布脚本提交或推送。如果发布后出现内联脚本解析错误，修复维护真源、重新生成并发布新的候选 commit。
